What is React?



  • Created by Facebook, used by Instagram, Airbnb, Netflix

  • Focuses on building small, reusable components

  • One of the most in demand frontend skills in the job market today

Library or Framework?


Here's the difference:


Library:

  • A collection of pre-written code you can pull from when you need it

  • You're in control, developers devide when and how to call it

  • Focused on solving a specific, narrow problem

Library or Framework?


Framework:

  • Provides a skeleton or structure for your application

  • Inverts control: the framework calls your code (“Inversion of Control”)

  • “Opinionated”: it tells you how things should be built, limiting flexibility to ensure consistency

Which one is React?



Core React (react + react-dom):

  • Technically, it's a JavaScript library

  • It focuses specifically on building user interfaces

In Practice:



  • React is often used as a framework because it shapes how you build UIs with components and a declarative style

  • When you add tools from the React ecosystem (React Router, Redux, Vite, etc.) it becomes a full framework-like experience

tldr;



  • On its own => Library

  • In practice => Framework

  • End of the day: doesn’t really matter


Why React is Popular



  • ✅ Easy to get started

  • ♻️ Component-based = Reusable code

  • ⚡ Fast updates

  • 🌍 Huge community + job market

  • 🤝🏻 Built for teams

Easy to get started



  • Uses the familiar HTML, CSS, and JavaScript

  • You're not starting from zero

Component-based thinking

  • Think of components like LEGO bricks
  • You build a "Button" or a "Card" once, and use it 20 times!

Fast Updates:



  • React only updates the parts of the page that actually changed

  • Instead of re-rendering the whole page


Huge community + job market:



  • High Job Demand

  • Lots of tutorials

  • Many discord/reddit groups

Team Development:



  • Multiple developers can build and test their components without messing up each other's work

  • reusable UI components (like buttons, modals, forms) mean everyone is pulling from the same set of building blocks

  • Makes development more efficient and maintainable with large teams

Key Features of React



  • Component-Based Architecture

  • Virtual DOM

  • Declarative UI

Component-Based Architecture



  • Apps built from small, reusable pieces called components

  • Think of Netflix: each movie card is a component, search bar is a component, the header is a component

  • They're all independent, and they all work together

Vertical Separation of Concerns:


  • Changes the focus from separating by file type (HTML, CSS, JS)...

  • ...to grouping by functionality

  • Everything for a component (content, styles, logic) lives together in one place

  • Allows for component reusability


Virtual DOM



  • React keeps a draft (Virtual DOM)

  • Updates only the changed parts

  • Makes apps faster and smoother




Declarative UI



  • Focus on what the UI should look like, not how to update it

  • i.e. You tell React what the UI should look like...



React takes care of the rest behind the scenes

What is JSX?



  • JSX = JavaScript XML

  • Lets you write HTML-like code in JavaScript

  • Notice the file extensions inside a React project .jsx




      const drink = "Margarita";
      return <h1>I would like a {drink}, please!</h1>

How is JSX different from HTML?



Why JSX is awesome?



Cleaner Code:

  • JSX looks like HTML, so it's easier to read

  • You can see the layout and the logic side by side

  • No need to switch between files

Why JSX is awesome?



Dynamic:

  • Use real JavaScript in your UI:

  • Use JavaScript expressions inside curly braces


      const drink = "Margarita";

      return <h2>I'd like a {drink}, please!</h2>;

Function Components



  • Component is essentially a JavaScript function

  • The name MUST start with a capital letter

  • It returns JSX, the UI for that component

Example




  const CocktailCard = () => {
    return (
      <div>
        <h2>Mojito</h2>
        <p>Minty and refreshing</p>
      </div>
    );
  };

Why Capital Letters?



  • When React sees <div>, it knows that's a standard HTML element

  • When it sees <CocktailCard>, the capital letter tells it this is a custom component, find the function and run it

What are Props?


  • Short for "properties"

  • Props are how you pass data into a component

  • Specifically, from a parent component to a child component

  • Can't be changed by the child (read-only)

Props Example (Parent)


  const CocktailMenu = () => {
    return (
      <div>
        <h1>Tonight's Menu</h1>
        <Cocktail
          liquor="tequila"
          mixer="grapefruit juice"
        />
      </div>
    );
  };

The parent is passing two props: liquor and mixer.

Props Example (Child)




    const Cocktail = ({ liquor, mixer }) => {
      return (
        <p>Your cocktail: {liquor} and {mixer}</p>
      );
    }

🎯 Child receives and uses the props!

Component Reusability


  • Components = Cocktail Recipes

  • Each recipe defines ingredients & presentation

  • Ingredients = Props

  • Customize your component's "flavor"

Define the Component




  // Define the recipe once
  const Mojito = ({ lime, mint }) => {
    return (
      <div>
        <h2>Mojito</h2>
        <p>Lime: {lime} | Mint: {mint}</p>
      </div>
    );
  };

Same Recipe, Different Cocktails!


    <Mojito lime="2 slices" mint="extra" />


    <Mojito lime="1 slice" mint="light" />

Same component, with different props, produces different results!

Building with Smaller Components


  • Props allow you to compose

  • Build bigger things from smaller building blocks

  • Each small component does one job, and you assemble them together

  • Compose like a master bartender!

Example




    // Renders an image
    const DrinkImage = ({ src }) => {
      return <img src={src} alt="cocktail" />;
    };

    // Renders a name
    const DrinkName = ({ name }) => {
      return <h2>{name}</h2>;
    };

Two components, each doing one job

Composing them together




    const CocktailCard = ({ name, image }) => {
      return (
        <div>
          <DrinkName name={name} />
          <DrinkImage src={image} />
        </div>
      );
    };
    // Using the finished card
    <CocktailCard name="Mojito" image="mojito.png" />

Why It's Awesome 🎉


  • Reusable: DrinkImage and DrinkName aren't locked inside CocktailCard, use them anywhere in your app

  • Customizable: Change props anytime

  • Organized: Each component has one job, makes code easier to read and update

  • Design your app like a bartender!

What is State vs Props?


Going back to our bartender analogy...



  • Props = what the customer orders

  • State = what's happening behind the bar

What is State?


  • State is like a component's memory

  • Data lives inside a specific component

  • Can change over time based on user clicks, timers, etc.

  • Automatically updates the UI when it changes

State Example: Ice Cubes 🧊


  • Start with 10 ice cubes in bucket

  • Every drink removes 2 ice cubes

  • Number left = your state

  • Changes over time!

What It Looks Like


🧊 Ice cubes: 10

🧊 Out of Ice!


👆 Click button → ice decreases → warning appears at 0!

State in React


    const IceBucket = () => {
      const [iceCubes, setIceCubes] = useState(10);

      const makeDrink = () => {
        setIceCubes(iceCubes - 2);
      };

      return (
        <div>
          <p>Ice cubes: {iceCubes}</p>
          <button onClick={makeDrink}>Make Drink 🍹</button>
          {iceCubes === 0 && <p>🧊 Out of Ice!</p>}
        </div>
      );
    };

State Characteristics


Summary


  • Data lives inside a component

  • Component can change it

  • Based on user clicks, timers, etc.

  • Updates the UI automatically

Putting it Together


Props

  • What the customer orders, external

  • Component can't change it


State

  • What's happening behind the bar, internal

  • Can change


Both essential for great drinks & UIs! 🎉



useState Hook



  • Built in React function

  • Allows you to add state variables to functional components

  • Must be imported from React library 

    • 
  import { useState } from 'react';

Key Characteristics


  • Gives function components memory

  • Like a bartender's notepad

  • Without it, component renders once and forgets everything

  • Updates UI when data changes

useState Example



    const [iceCubeCount, setIceCubeCount] = useState(10);

    // iceCubeCount = current value (how many ice cubes left)
    // setIceCubeCount = function to update number of ice cubes

    // When someone orders:
    setIceCubeCount(iceCubeCount - 2);

🎯 React updates the screen automatically!

Why useState is Awesome 🎉


  • Simple way to manage changing data

  • Works great in function components

  • Keeps UI in sync with real-time updates

  • Handles clicks, forms, timers, etc.


useEffect Hook



  • Tells React to do something after rendering

  • Used for things like fetching data, setting up a timer, listening to events

  • These are called side effects

The Bartender Analogy



When someone picks a drink from the menu...


🍹 You automatically start making it!

useEffect Example


    import { useEffect, useState } from 'react';

    const CocktailMaker = ({ selectedDrink }) => {

      useEffect(() => {
        console.log(`Making a ${selectedDrink}... 🍹`);
      }, [selectedDrink]);

      return <h2>Your {selectedDrink} will be ready soon!</h2>;
    };

🎯 Every time the drink changes, make a new one!

When Does useEffect Run?


  • After component renders

  • When dependencies change

  • Before component unmounts (cleanup)



🍹Like a bartender who responds to orders!

Dependency Arrays



  • Tell React when to run the effect

  • Only run when these values change

Dependency Array Examples


No Array:

  • useEffect(() => {...})

  • Runs on every render (too much mixing!)


Empty Array:

  • useEffect(() => {...}, [])

  • Runs once on mount (bar setup)

Dependency Array Examples


With dependencies:


  • useEffect(() => {...}, [drink])

  • Runs when drink changes

useEffect Summary



  • Run code after component renders

  • Control when effects run with dependencies

  • Perfect for data fetching and side effects

  • Always include dependencies

  • Avoide infinite loops! Don't forget dependency arrays

Handling User Interactions


onClick: When a User Orders a Drink


  • React listens for user interactions (clicks, typing, form submission)

  • React responds instantly by running a function

  • State updates automatically

onClick Example


    const makeMojito = () => {
      setMojitoCount(mojitoCount + 1);
      console.log("1 Mojito served! 🍹");
    };

    <button onClick={makeMojito}>
      Make Mojito
    </button>

👆 Click → Function runs → UI updates!

onChange: Choosing Ingredients


  • noChange fires every time the selected option changes

  • React listens for the change

  • Updates the value of whatever the user selected

  • 🍸 Like picking what to mix!

onChange Example


    <select onChange={(e) => setJuice(e.target.value)}>
      <option value="orange">Orange Juice</option>
      <option value="pineapple">Pineapple Juice</option>
    </select>

🎯 Every change updates the state!

Form Inputs: Custom Cocktail Orders


  • Customer enters their name

  • Selects what they want to order

  • Submits the complete order

  • Order goes to the bartender!

What the Form Looks Like


Form Example


    <form onSubmit={handleSubmit}>
      <input
        type="text"
        value={name}
        onChange={(e) => setName(e.target.value)}
      />
      <button type="submit">Place Order</button>
    </form>

Why This is Powerful 🎉


  • Respond to clicks (drink buttons)

  • Track changes (ingredient selections)

  • Handle full orders (submitting requests)

  • From showing things... to doing things!

Conditional Rendering



  • Used to show different things based on conditions

  • React gives us three main tools for this

  • 🍸 if, ternary operators, &&

if Statement: Choose by Mood


Use a regular if / else if / else when you have more than two possible outcomes:


  • Relaxed → Mojito

  • Fun → Margarita

  • Default → Water

  • Just like regular JavaScript!

if Statement Example


    const CocktailSuggestion = ({ mood }) => {
      let suggestion;

      if (mood === 'relaxed') {
        suggestion = 'Mojito';
      } else if (mood === 'fun') {
        suggestion = 'Margarita';
      } else {
        suggestion = 'Water';
      }

      return <h2>Try a {suggestion}!</h2>;
    }

Ternary Operator: Choose Between Two


  • Yes/no questions

  • "Are you 21 or older?"

  • Yes → Margarita

  • No → Mocktail

Ternary Operator Example


    const CocktailCheck = ({ age }) => {
      return (
        <p>
          {age >= 21 ? 'Here\'s your Margarita!' : 'Here\'s a nice Mocktail!'}
        </p>
      );
    }

💡 Quick one-line if...else!


The format is always: condition ? value if true : value if false

Logical && : Only Show If True



  • Show something only if condition is true, no else needed

  • Only show "Place Order" if drink selected

  • No drink = no button

  • Drink selected = show button

Logical && Example



    const OrderButton = ({ selectedDrink }) => {
      return (
        <div>
          {selectedDrink &&
            <button>Place Order for {selectedDrink}</button>
          }
        </div>
      );
    }

💡 If no drink, React shows nothing!

All together Example


  const CocktailApp = ({ mood, age, selectedDrink }) => {
    let suggestion;

    if (mood === 'relaxed') { suggestion = 'Mojito'; }
    else if (mood === 'fun') { suggestion = 'Margarita'; }
    else { suggestion = 'Water'; }

    return (
      <div>
        <h1>Welcome to the Cocktail Bar 🍸</h1>
        <h2>{age >= 21 ? 'Adult Menu' : 'Mocktail Menu'}</h2>
        <p>Suggestion: {suggestion}</p>
        {selectedDrink && <button>Order {selectedDrink}</button>}
      </div>
    );
  };

Conditional Rendering Summary


  • if statements → Multiple conditions

  • Ternary → Two options (true/false)

  • && → Show only if true

  • Perfect for dynamic UIs!

Small, Reusable Components



  • Think like a bartender!

  • Every component should have one clear job

  • Don't make every drink from scratch


🎯 The goal is small, reusable pieces that can be dropped anywhere

Example


    const DrinkImage = ({ src }) => {
      return <img src={src} alt="cocktail" />;
    }

    const IngredientsList = ({ items }) => {
      return (
        <ul>
          {items.map(i => <li key={i}>{i}</li>)}
        </ul>
      );
    }

😊 Reusable in any cocktail!

Separation of Concerns (SoC)


Keep different responsibilities in different places


  • UI/Presentational: displays data, no logic

  • Logic/Container: manages state, fetches data

  • Styling: visual appearance .css file

File Structure Recommendations



Organize like a professional bar! 🏪



Each component gets its own "station"


    /src
    │
    ├── /components
    │   ├── /CocktailCard
    │   │   ├── CocktailCard.jsx       ← Component logic + JSX
    │   │   ├── CocktailCard.module.css ← Styles scoped to this component
    │   │   └── index.js               ← Clean export
    │   │
    │   └── /DrinkList
    │       ├── DrinkList.jsx
    │       └── index.js
    │
    ├── /pages
    │   ├── Home.jsx
    │   └── About.jsx
    │
    └── App.jsx                        ← Root component

React Best Practices



  • Organize components in folders

  • Keep components small and focused

  • Separation of concerns: UI, logic, and state

  • Reuse components with props

  • Add comments and meaningful names

  • Keep JSX clean and readable
